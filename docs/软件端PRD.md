## 1. 产品概述

### 1.1 背景

我们做的是**环境健康智能体（Agentic Device）**——安装在家庭马桶上，四传感器（毫米波/热成像/光谱/气味，无可见光）被动感知，agent 主动把数据变成用户能理解、愿意持续使用的东西。核心不是"App 里的聊天窗口"，而是"它来找人，不是人找它"：用户什么也不用做，agent 主动汇报、主动建议、主动照看每个家庭成员。产品定位出海，先做网站（后期独立站），再 iOS、Android、微信小程序。

### 1.2 产品定位

一个"便便健康助手"：每次如厕后，把检测结果变成**一个可爱的形象 + 一句看得懂的建议**，并长期跟踪趋势，让用户轻松了解自己的肠道健康。

### 1.3 核心价值（一句话）

把冷冰冰的传感器数据，变成用户每天愿意看一眼的健康反馈。

### 1.4 产品目标（可衡量）

- **MVP 目标**：跑通"数据 → 形象 → 建议 → 趋势"闭环，单次检测从出数据到 App 展示结果 ≤ 10 秒；建议能覆盖常见形态/颜色类别。
- **长期目标**：养成用户每日记录习惯，提升次日/次周留存率。

---

## 2. 目标用户与使用场景

### 2.1 目标用户

关注肠道健康、愿意日常记录的普通用户（**非医疗诊断用户**）。

### 2.2 核心场景

用户如厕 → 设备检测 → 用户在网站/App 看到今天的便便形象 → 收到一句建议 → 查看长期趋势 →（后期）养宠物、分享打卡。

---

## 3. 产品范围与分期

### 3.1 范围内 / 范围外

**范围内**：便便形象化、健康建议、长期趋势、健康档案（自报问卷）、家庭共享、养成游戏、匿名分享。

**范围外**：医疗诊断、处方、治疗建议（见 §6 合规红线）。

### 3.2 分期

| 阶段 | 内容 | 目标 |
| --- | --- | --- |
| 阶段 1（核心闭环） | 可靠数据链路 → 成员认领 → 规则建议与趋势 → 主动通知与家庭授权 | 先做到数据可信、归属明确、结果可解释且通知可控 |
| 阶段 2（记忆与留存） | 可见可改的分区记忆 → 便便宠物/打卡 | 提升个性化与留存，不阻塞阶段 1 |
| 阶段 3（扩展） | 匿名社交 → 多 Agent 编排 | 在权限、审计和核心链路稳定后接入 |

## 4. 功能需求详述

> 每条功能按：优先级 / 需求描述 / 用户故事 / 功能要点 / 验收标准 展开。

### 4.1 【P0】数据接入与便便档案（地基）

**优先级**：P0（最高，其他功能都依赖它）

**需求描述**：定义"一次便便检测"的标准数据格式（便便档案），并接收硬件输出的结果。

**用户故事**：作为系统，我希望每次检测都产出结构化的便便档案，以便上层功能（形象/建议/趋势/游戏/社交）统一读取。

**功能要点**：
- 数据按采集会话、传感器观测、成员归属、健康评估、Agent 行动五类保存（见《硬件对接说明》§3 数据接口契约）。
- 硬件不直接产出可信的最终 `member_id`，只可给候选成员和置信度。无法可靠识别时，会话进入家庭“待认领箱”；用户认领后才进入个人档案、趋势和定向推送。
- 认领错误可纠正；认领和纠正以新版本保存，不能覆盖原始传感器观测。
- “待认领箱”按家庭展示待处理会话、采集时间和可安全展示的结果摘要；具备家庭管理权限的用户可选择成员或标记“无法认领”。认领操作须记录操作者、方式、时间和版本。
- 新增时长字段：`timestamp`（坐下）/ `end_timestamp`（起身）/ `duration_s`（持续时间）。时长是便秘的辅助信号，与 shape（三档）交叉验证，不单独下结论。
- 后端提供受控 API；其他功能不得绕过策略层读取或修改原始健康数据。
- 数据写入与 outbox 事件在同一数据库事务完成，后台任务使用幂等键、有限重试和失败状态，防止重复建议、漏推送。

**硬件当前实际输出（2026-08-22 旧格式）**：Python 给 LLM 的 user message 仍使用 `event_id / color_category / color_confidence / odor_deviation / odor_change_pct / odor_confidence / temperature_c / humidity_pct / sample_quality`。该格式仅由兼容适配层接收；需要升级为 v1.0 的会话、版本、质量、序号和时间字段。最终 `member_id` 不由硬件强制提供；shape、颜色和气味取值仍待对齐——详见《硬件对接说明》§3。

**验收标准**：
- 硬件四传感器输出能按约定格式进入后端并成功落库。
- 能按时间查询已认领成员的历史档案；待认领会话不会混入任何成员趋势。
- 字段缺失或异常时（如 shape 未上线、气味缺失）系统能降级处理而不崩溃。
- 重复上传、断网补传不会产生重复档案或重复通知。
- 待认领会话不会触发任何成员定向建议或推送；认领后只触发一次后续评估，纠正归属后旧成员趋势失效、新成员趋势重算且保留审计记录。
- 对正常、缺字段、重复上传、离线补传、未认领和认领纠正样例均有自动化验收用例。

### 4.2 【P0】便便形象化

**优先级**：P0

**需求描述**：每次检测根据颜色、形状、气味生成一个对应的可爱便便动画形象。

**用户故事**：作为用户，我希望看到我今天的便便是什么样，以便直观了解这次结果。

**功能要点**：
- 建立"映射表"：形状三档（hard/normal/loose）→ 身体造型；颜色类别 → 皮肤/配色；气味类别 → 表情/特效。
- 若气味由硬件无法测得，支持用户手动勾选（很臭/一般/不臭）作为降级方案。
- 由设计师提供形象资产，程序按映射表选对应动画（不做实时 AI 生成，保证稳定）。

**验收标准**：
- 同一份数据输入，多次生成形象一致（确定性）。
- 覆盖形状三档和至少 5 种颜色类别的映射。
- 形象在 App 内能正常播放动画。

### 4.3 【P0】Agent 健康建议

**实现状态（2026-08-27）**：Agent 医生已接后端真实模型适配器。每次请求先校验家庭和成员查看权，再由规则引擎给出风险走廊与动作白名单，LLM 只能在白名单内解释；对话、模型版本、授权依据和审计行动均持久化。模型未配置时界面明确提示配置，不显示伪造回答。

**模型决策（2026-08-28）**：使用 DeepSeek `deepseek-v4-pro`；主动调度默认开启，但必须由服务端密钥激活。当前阶段不增加登录和个人信息采集，继续使用既有开发身份验证闭环，登录作为独立安全单元后续实施。

**可见闭环（2026-08-28）**：用户重新进入 Agent 医生时恢复本人最近对话；医生页显示模型是否连接、主动调度是否运行；“我的”页显示本人 Agent 行动及完成/待执行/取消状态。用户界面不展示其他家庭成员的模型输入摘要。

**记忆实现（2026-08-28）**：健康页已提供 Agent 记忆区。新增自报和修改自报会生成版本；系统推断可纠正并记录纠正原因；传感事实显示“事实锁定”，后端同样拒绝覆盖。家庭查看授权允许查看记忆，但不隐含编辑权。

**优先级**：P0（核心差异化）

**需求描述**：每次检测后，Agent 基于结果给出生活方式建议（吃/睡/喝），并猜测可能的相关原因。

**用户故事**：作为用户，我希望每次检测后知道"这代表什么、我该注意什么"，以便调整生活习惯。

**功能要点**：
- 两层实现：① **规则引擎**（确定、安全）——由专业审核的对照规则，如"形状 hard（干硬）→ 通常对应缺水/纤维不足 → 建议多喝水、多吃蔬菜"；② **LLM + 知识库（RAG）**——把建议说得自然、支持追问和解释。
- 建议范围限定在**生活方式**（饮食/饮水/睡眠/运动），不做诊断。
- 前面加**红线拦截层**（见 §6.3）：命中危险信号时不下结论，直接提醒就医。

**验收标准**：
- 对形状三档和主要颜色类别都能给出对应建议。
- 对系统已可靠识别的红线信号，100%进入安全流程并输出“建议就医”而非具体建议。
- 低置信度或关键输入缺失时明确显示“本次无法可靠判断”，不输出弱结论或制造“没提醒就是安全”的错觉。
- 建议内容有知识库来源，可追溯。

### 4.4 【P0】长期趋势与轨迹判断

**优先级**：P0

**需求描述**：按时间持久化保存每次档案，生成趋势图，并由 Agent 判断趋势。

**用户故事**：作为用户，我希望看到我最近一个月的变化趋势，以便知道自己在变好还是变差。

**功能要点**：
- 档案持久化存库（注意：这与硬件端"最近 60 秒滑动窗口"不同，是新的**长期存储**）。
- 按日/周/月生成频率、形状/颜色类别占比、连续异常、个人基线偏离和有效样本覆盖率；类别数据不直接求平均。
- Agent 读取汇总结果做"轨迹判断"（如"你最近便便越来越干，注意补水"）。

**验收标准**：
- 历史档案能正确存储和按月查询。
- 趋势图数据正确、可读。
- Agent 能基于趋势给出判断语句。
- 趋势同时展示有效样本数/覆盖率；覆盖不足时不输出方向性判断，而是提示数据不足。
- 未认领、已作废归属及低质量样本不计入个人趋势；归属纠正后相关汇总可重算且结果一致。
- 长期变化在一张用户友好的漫画式卡片中整合形状、颜色与气味；只表达“接近日常/变化明显/积累中”和真实类别构成，不展示雷达建模术语，不虚构逐日联合分布。

### 4.5 【P1】养成游戏（便便宠物）

**优先级**：P1

**需求描述**：基于个人便便档案的养成类小游戏，用真实数据驱动宠物状态。

**用户故事**：作为用户，我希望有个可爱的宠物反映我的健康，以便每天愿意回来看看。

**功能要点**：
- 以"养一只便便宠物"为内核：宠物外观/心情由真实档案驱动，连续健康升级进化，连续不健康变蔫。
- 宠物说的话复用 Agent 建议（如"我有点干干的，给我喂点水吧"）。
- 收集系统：不同状态解锁皮肤/图鉴；配套连续打卡 streak。

**验收标准**：
- 宠物状态与用户近期真实档案一致。
- 游戏只读健康档案，不能修改档案数据。
- 打卡连续天数统计正确。

### 4.6 【P2】匿名分享与社交

**优先级**：P2

**需求描述**：用户可把匿名打卡卡片分享出去（不暴露真实身份和健康细节）。

**用户故事**：作为用户，我希望在不泄露隐私的前提下分享我的打卡，以便获得激励。

**功能要点**：
- 第一步只做**匿名打卡卡片**：可爱便便形象 + 一句状态 + 匿名昵称，不含真实姓名/年龄/病症/具体数值。
- 卡片文案由 Agent 生成，生成后走敏感词与隐私过滤。
- Agent 交友（ANP）分三级：L1 人工授权匹配（MVP 只做这个）→ L2 半自动推荐 → L3 全自动 agent 社交（远期愿景）。
- 后续按需扩展：匿名排行榜 → 结伴打卡 → 匿名社区（需内容审核）。

**验收标准**：
- 分享卡片不含任何可识别个人身份或具体检测数值的信息。
- 分享默认关闭（用户主动开启 opt-in）。

### 4.7 【P1】家庭共享

**优先级**：P1

**需求描述**：一台家庭马桶多人共用。硬件成员识别能力尚未确认，软件通过“候选成员 + 待认领 + 用户确认”完成归属，并支持家庭成员之间查看/代管档案。

**用户故事**：作为家长或子女，我希望看到家人的健康状态，以便照看孩子或父母。

**功能要点**：
- 三种角色：管理员（自己）、被监护者（孩子/老人，由管理员代管）、查看者（家人互看，需授权）。
- 按成员隔离：每个成员独立档案，不是全家一个档案。
- 授权与撤回：查看他人档案需对方授权，可随时撤回。
- 红线同步：已授权家庭查看者会同步收到红线事件；撤回授权后，查看权限和红线通知立即同时失效。

**验收标准**：
- 同一家庭的数据按 `member_id` 正确分流到各自档案。
- 未授权成员无法查看他人档案。
- 授权可随时撤回，撤回后立即失效。
- 红线事件只同步给当时仍具有效授权的查看者，并记录接收人和授权依据。
- 授权范围明确包含“查看档案 + 接收红线通知”，授权页在确认前展示两项影响；撤回后新查询与新通知立即被拒绝。
- 撤回与红线事件并发时，以通知发送前的最终授权校验为准；无有效接收人时仅通知本人并记录原因。

### 4.8 【P0】健康档案（自报层）

**优先级**：P0（冷启动钩子 + agent 记忆种子 + 建议可靠性地基）

**需求描述**：用户主动填写的健康档案（病史/饮食/作息/用药/目标），是三层数据模型的自报层，回答"为什么"（传感器只能给"结果"）。

**用户故事**：作为用户，我希望通过填问卷让 agent 更懂我、给我更准的建议，并随时能改。

**功能要点**：
- 最小可用问卷：病史/饮食/作息/用药/目标，别贪多。
- 对话式 + 点选卡片采集（好玩），不是死表单。
- 每条自报数据标 provenance（`self_report`），与传感数据（`sensor`）区分。
- 这就是 agent 记忆（USER.md/MEMORY.md）的"可见可改"版，落在"健康"导航区。
- 记忆按来源分为用户自报、传感事实和系统推断：用户可修改自报信息、纠正系统推断，但不能覆盖原始观测；所有修改形成新版本并可追溯。
- 免费健康评估当钩子（借鉴 LEMONBOX），解冷启动。

**验收标准**：
- 用户能填写并随时修改健康档案。
- 自报数据与传感数据分开存、分别标来源。
- agent 给建议时能引用自报数据（如"你填了常吃辣，最近又便偏干…"）。
- 用户能查看每条记忆的来源、当前值和修改记录；可修改自报、纠正推断，但不能编辑或删除原始观测事实。
- 记忆纠正后生成新版本，后续建议读取最新有效版本，历史审计仍可查询。

## 5. 非功能需求

### 5.1 性能
- 单次检测结果在 App 展示 ≤ 10 秒（MVP）。
- Agent 建议生成延迟可控（建议使用轻量模型或预生成常见规则文案兜底）。

### 5.2 安全与隐私
- 健康数据加密存储、传输加密（HTTPS/TLS）。
- 原始传感器数据默认不上云，只在设备本地短期滚动保存；用户专项授权后才可限期上传，并支持撤回和删除。
- 专项授权界面必须展示上传用途、数据类型、保留期限和撤回/删除入口；不得与基础服务授权捆绑或默认勾选。
- 社交/游戏只读健康档案，且需用户授权。
- 匿名化是硬要求：任何对外分享不得含真实身份和具体数值。

**隐私验收**：未授权时原始数据上传请求被拒绝；授权后仅允许约定类型与期限；撤回后停止新上传，云端副本进入可追踪删除流程并向用户显示删除状态。

### 5.3 可用性
- 面向普通用户，文案通俗、避免医学术语堆砌。
- 首次使用有引导（怎么检测、形象代表什么）。

## 6. 合规与红线

### 6.1 医疗边界

本产品是**健康生活方式辅助**，不是医疗器械，不做诊断、不开处方。

### 6.2 隐私合规

涉及健康数据，需符合数据最小化、用户授权、可删除等基本要求；MVP 阶段暂不引入法务，但红线拦截（§6.3）技术上先做。

### 6.3 红线拦截清单（Agent 输出前必须拦截）

风险定级、接收人、通知频率和允许动作由**确定性策略层**决定，LLM 不得修改；LLM 只在已放行范围内生成解释。工具执行前再次校验授权并记录审计。对于系统已可靠识别的以下信号，Agent **不下结论、不给饮食建议，直接提醒就医并同步已授权家庭查看者**：

- 便血 / 黑便 / 陶土色便
- 连续腹泻或便秘持续数周
- 体重短期内明显下降

若相关传感器置信度不足或关键输入缺失，界面必须明确显示“本次无法可靠判断”，不得以弱语气继续输出健康结论。

## 12. 便便宠物与打卡验收补充（2026-08-28）

1. 每位成员拥有独立宠物档案；家庭公共 Agent 不共享或改写宠物名字、皮肤和成长进度。
2. 每日打卡最多计一次，重复请求返回已打卡状态，不重复累计。
3. 宠物只能读取已放行的可靠健康摘要；可靠样本不足时显示探索状态，不输出健康弱结论。
4. 打卡、成长和皮肤不得写入采集会话、传感观测、成员归属或健康评估表。
5. 默认皮肤立即可用，累计 3 次与 7 次打卡解锁后续皮肤；未解锁皮肤由服务端拒绝。
6. 有效家庭查看授权允许查看宠物状态，但不允许代打卡、改名或换肤；授权撤回后读取立即失效。
7. 本单元位于广场，不增加首页入口，不开发登录页面。

## 13. ANP 社区验收补充（2026-08-29）

1. 每条社区发布必须在本次操作中显式确认公开，不提供默认勾选或永久自动同意。
2. 只发布用户手写的 2–280 字正文和所选主题；不得自动带入原始观测、健康趋势、Agent 记忆、成员姓名或家庭身份。
3. 社区响应只展示 Agent 别名、主题、正文和时间，不暴露内部用户、成员、家庭 ID。
4. 家庭查看授权不包含社区代发权；viewer 不得替成员发布。
5. 作者或所属家庭 owner 可撤回；撤回后立即从社区 active 列表消失，审计记录保留。
6. 发布、撤回均记录动作类型、授权依据、策略版本、结果和幂等键。

## 14. 多专家综合分析验收补充（2026-08-29）

1. 前台仍只呈现一个主 Agent，但必须明确显示健康医生、生活教练与安全仲裁的调用轨迹。
2. 健康医生负责风险解释；生活教练只给饮水、饮食、运动和作息等低风险行动。
3. 生活教练不得读取近期评估或完整健康记忆，只读取趋势、自报记忆和允许动作。
4. 最终仲裁必须是确定性代码，优先级为策略规则、健康风险、生活建议，不允许 LLM 自行改变优先级。
5. 红线命中必须直接进入紧急安全流程，不因用户要求“综合分析”而降级。

## 15. L1 Agent 匹配验收补充（2026-08-29）
