## 1. 项目一句话

**PoopSense（中文名"便知"），slogan：See. Smell. Sense.（不用拍照，也能读懂每一次身体信号）** —— 一款安装在家庭马桶上的**环境健康智能体（Agentic Device）**：四类传感器（压力+APDS9960 / MLX90640 / AS7341 / BME688，无可见光）被动感知，Agent 主动把可靠数据变成“可爱形象 + 看得懂的建议 + 长期趋势”，主动关心每个家庭成员。出海产品（目标美国），先做网站。近期目标：冲刺 GOSIM Spotlight Shenzhen 2026（首轮 9/13 截止）。

## 4. 当前进度（已拍板 ✅ / 外部待确认 ⏳）

**已拍板**：
- 第 4 页改"我的/设备"（登录做前置流程）
- ANP 分三级做（MVP 只做 L1 人工授权匹配）
- 家庭马桶多人共用；成员归属单独记录，确认后关联 `member_id`，未确认时进入待认领箱；家庭共享按成员和授权隔离
- 出海，先网站 → iOS → Android + 微信小程序；设备倾向 WiFi 直连
- 付费模式：AI 免费 + 健康管理付费
- 知识库 MVP1 用公开资料，后期找专业机构
- 战略：前期泛娱乐 → 后期有数据走高质量
- 品类定位：环境健康智能体（Agentic Device），"它找人不是人找它"
- 四类传感器型号（据 BP）：压力+APDS9960（识别成员+在场起止）、MLX90640（形状）、AS7341（颜色）、BME688（气味），无可见光；成员靠压力匹配，APDS9960 做在场检测
- 近期目标：冲刺 GOSIM Spotlight（9/13 截止，开放创新方向）
- 成员识别不可靠时进入家庭“待认领箱”；认领前不进入个人趋势、不做定向推送
- 低置信度或关键输入缺失时明确显示“本次无法可靠判断”，不输出弱结论
- 保留健康/家庭/宠物/社交/多 Agent 完整范围，但按核心闭环优先分阶段接入
- Agent 记忆对用户可见可改，修改形成新版本，不覆盖原始观测
- 原始传感器数据默认不上云；专项授权后才限期上传，可撤回、可删除
- 红线事件同步通知已授权家庭查看者；撤回授权后立即停止查看与通知

**外部待确认（不阻塞软件 mock 开发）**：
1. 硬件颜色枚举与真实场景阈值。
2. 气味偏离度/绝对分类口径与阈值。
3. shape 三档的硬件判定能力与成员识别（压力匹配）的稳定性。
4. 最终通信方式、供电方案及各 sensing 稳定输出时间。

### 2026-08-28 模型与登录决策

- 模型供应商确定为 DeepSeek，模型使用官方 API 标识 `deepseek-v4-pro`，OpenAI-compatible 基址为 `https://api.deepseek.com`。
- 主动调度默认开启；只有服务端存在 `POOPSENSE_LLM_API_KEY` 或 `DEEPSEEK_API_KEY` 时才真正进入 outbox，避免无密钥任务反复失败。
- 本轮暂不接登录与个人信息采集。原因不是功能做不到，而是登录会改变授权主体和密钥边界；先完成真实模型联调，再独立设计账号迁移和隐私同意流程，风险更可控。
- Agent 可见闭环已补齐：医生页恢复当前用户最近一次对话并展示模型/主动调度状态；“我的”页展示当前用户实际接收的 Agent 行动、执行状态和时间。行动列表不返回输入全文或其他成员记录。
- 可见可改记忆已落地：健康页可新增和修改用户自报、纠正系统推断；传感事实在接口和数据库层均不可覆盖。每次修改追加新版本，旧版本保留审计，DeepSeek 只读取当前有效版本。

### 2026-08-28 Agent-native 决策

- 每位家庭成员拥有独立主 Agent 与独立 Soul；家庭管家是家庭公共 Agent，不与个人 Soul 混用。
- 前台只呈现一个主 Agent，发生委派时明确显示“正在调用健康医生 / 生活教练 / 家庭管家”及所用 Skill。
- 首批 Skill 注册表包含记录解释、趋势总结、健康解释、红线安全处理、普通主动关怀和家庭事务；模型只能选择注册能力，权限仍由后端护栏决定。
- 普通主动关怀默认每 24 小时最多一次，支持成员级一键关闭和静默时段；红线安全流程不受静默限制。
- Soul 包含 Agent 名称、相处语气和长期关系目标，用户可编辑并保留版本号；传感事实和安全策略不属于 Soul，不能被其覆盖。

### 2026-08-28 Skill 暂停与恢复

## 6. 软件开发进度（2026-08-24）

### 2026-08-30 机械臂取水演示闭环（当前口径）

- Agent 不能生成或发送任意关节角；确定性规则只在饮水/补水语境下返回 `offer_water_pickup` 许可。
- 当前演示链路收敛为“结果动画 → Agent 分析 → 补水建议 → 用户二次确认 → 机械臂原地取杯、夹紧、提起并保持”。不调用 VBot，不移动，不进入交接位，也不松爪。
- 前端只展示受限的“准备取水 / 确认开始取水 / 停止机械臂”控件；标定仍只通过独立上位机或管理接口完成，用户前端不暴露关节角和轨迹编辑。
- 取水只要求待机、取水预备、抓取、抬起四个已标定姿态。上位机离线、Demo 模式、任务进行中或姿态缺失时，后端硬拒绝启动。
