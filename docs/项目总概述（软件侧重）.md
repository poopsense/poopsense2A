## 1. 一句话说明白这是什么

**PoopSense（便知）—— 一个装在家庭马桶上、不用你动手、会主动来关心你的"便便健康管家"。**

它不是"又一个健康 App"，而是一个**环境健康智能体（Agentic Device）**——设备安在马桶上被动感知，agent 主动来找你："Sam 这周 3 次稀便 + 喝水偏少，要看看吗？" 而普通健康 App 是你主动打开去问它。

这个区别（**"它来找人，不是人找它"**）是整个项目的题眼，也是 GOSIM Spotlight Shenzhen 2026（首轮 9/13 截止）评审最看重的"Agent 原生程度"。

---

## 2. 品类命题

**一个住在卫生间里的家庭健康智能体（Ambient Health Agent）**——把一天里最被忽视的生理信号，变成一个持续在场、主动关心每个家庭成员的环境智能体。

为什么不能只是 App：**没人会主动打开 App 记录排便**，必须有一个不打扰、被动感知、主动汇报的设备。

为什么今天能做：传感器消费级化 + LLM 成熟 + **无可见光（不用摄像头）** 隐私方案可行，三者今天才同时成立。

---

## 3. 产品形态：硬件感知 + 软件思考

**硬件端（队友负责）**：马桶上一个无可见光的设备，四个传感器（都在 PoC 早期，形状最落后）：

| 传感器 | 干什么 | 现状 |
| --- | --- | --- |
| 压力 + APDS9960 | 识别成员（压力匹配）+ 标记起止（接近检测） | 🟢 成员识别/起止已通 |
| MLX90640 热成像 | 看形状（轮廓+体量） | 🔴 从头弄（目标三档） |
| AS7341 光谱 | 看颜色 | 🟡 12cm 能测卡纸；最小面积未测 |
| BME688 | 闻气味（VOC 指纹） | 🟡 能采 4 项；分类未跑通 |

**软件端（我负责）**：把数据变成用户愿意每天看一眼的东西——可爱形象、一句建议、长期趋势，并且 agent 主动推送。

---

## 4. 软件架构：五层 + 可审计事件主线

```
设备接入 → 采集会话 → 传感器观测 → 成员归属 → 健康评估 → Agent 行动 → 前端
                         ↑                ↓
                    待认领箱        审计/反馈/重试
```

| 层 | 职责 | 一句话 |
| --- | --- | --- |
| 接入层 | 接住设备数据 | 解析/校验/去重 |
| 后端层 | 数据 + 人 + 家庭 | 五类可审计数据、成员待认领、趋势、API（FastAPI + Postgres） |
| Agent 层 | 主动做事（核心） | 5 步闭环，见下 |
| 前端层 | 4 个导航区 | 出海 Web 优先（React/Vue + PWA） |
| 运营层 | 越用越准 | 追踪"建议准不准、用户看不看" |

---

## 5. Agent 层：真 agent，不是套壳

**套壳 vs agent 的区别，不在调不调大模型，在会不会主动做事**（自主触发 + 工具调用 + 记忆反馈闭环）。

**真 agent 的 5 步闭环**：

```
触发（事件：数据到达/定时/异常）→ 读记忆（基线+历史+画像）→ 决策（LLM 调度：说什么/调哪个工具）→ 执行（工具：推送/报告/购物清单/家庭共享）→ 观察+更新记忆
```

**关键分工**：**确定性策略层决定风险、权限、接收人、通知频率和允许动作；LLM 只在已放行范围内解释和组织语言。** 工具执行前再次校验授权并写审计日志，LLM 不能扩大接收人、披露范围或越过医疗红线。

**安全红线**：对系统已可靠识别的便血/黑便/陶土色等信号，100%进入安全流程；低置信度或缺失时明确显示“本次无法可靠判断”，不能让用户产生“没提醒就是安全”的错觉。

---

## 6. 核心功能 + 三层数据模型

**5 个功能**：① 形象化（便便→可爱卡通）② 健康建议 ③ 长期趋势 ④ 养成游戏（便便宠物）⑤ 社交（匿名+AI广场+agent交友）。

**4 个导航区**：首页（形象+问答）/ 健康（趋势+健康档案+家庭共享）/ 社交 / 我的·设备。

**三层数据模型（可靠性源于全方位）**：

| 层 | 数据 | 回答 |
| --- | --- | --- |
| 自报层 | 问卷：病史/饮食/作息/用药/目标 | "为什么"（原因） |
| 传感层 | 便便事件：颜色/形状/气味/时长 | "结果" |
| 反馈层 | 采纳/结果 | "有没有用" |

**问卷做好玩**（对话式 + 点选卡片），既解冷启动（免费评估当钩子，借鉴 LEMONBOX），又是 agent 记忆的种子。每条数据标 **provenance**（sensor/self_report/inferred）。

---

## 7. 数据契约 + 容错降级

**骨架已定**：数据分为采集会话、传感器观测、成员归属、健康评估、Agent 行动五类；接口统一携带 schema/device/household/firmware/model 版本、时间、序号、来源和链路标识。`member_id` 不再假定由硬件可靠给出。

**取值待补**：颜色枚举、气味分档、shape 判定，以及毫米波能否提供成员候选和置信度；最终成员归属由后端认领流程决定。

**容错降级是硬需求**：硬件明确“综合准确率会连锁反应”，所以软件不能假设每维都可靠——每维独立携带 confidence、缺失原因、模型版本和来源。非关键维缺失时，仅允许生成不依赖该维的确定性展示；关键输入缺失或低置信度时明确显示“本次无法可靠判断”，不输出“可能……”式弱健康结论，也不得用默认正常值补齐。

原硬件字段 `sample_quality` 实际表示“人在不在”，因此废弃该误导命名，拆为 `presence_state`、`collection_state` 和真正的 `quality`；每个观测独立保存置信度、缺失原因、模型版本与来源。

**成员归属**：硬件只提供候选成员和置信度。无法可靠识别时会话进入家庭“待认领箱”；认领前不进入个人趋势、不生成定向推送。认领与纠正均保留版本历史。

**原始数据政策**：默认只上传分类结果、特征摘要和质量信息；原始数据在设备本地短期滚动保存，只有用户专项授权后才限期上传，并支持撤回和删除。

## 8. 分期路线

完整产品范围保留，但扩展模块不得阻塞核心链路，接入顺序固定为：

1. **可靠数据链路**：版本契约、设备身份、去重、补传、失败状态。
2. **成员认领**：候选成员、待认领箱、认领纠正和独立档案。
3. **规则建议与趋势**：低置信度降级、类别占比、连续异常、基线偏离和有效样本覆盖率。
4. **主动通知与家庭授权**：接收人、频率、撤回即时生效和红线同步审计。至此完成核心闭环。
5. **记忆**：来源分区、用户可见可改、修改留痕。
6. **宠物**：只读已放行的健康摘要，不影响健康事实。
7. **社交**：匿名、主动授权、内容与隐私过滤。
8. **多 Agent 编排**：在最小权限、分区记忆和工具审计成熟后接入。

核心验收覆盖正常、缺字段、低置信度、重复上传、离线补传、成员未认领、认领纠正、授权撤回和红线通知九类场景。

---

## 9. 壁垒

**不在"用了 AI"，在"记忆 × 评估 × 运营"飞轮越转越准。** 三层：AI 分身+记忆文件（信任）/ 双向 AI 评估（吸收情绪成本）/ 运营驱动质量控制（复盘）。外加品类定义权（第一个定义"环境健康智能体"）+ 软硬一体 + 健康数据切换成本高。

## 10. 当前状态与下一步

> 2026-08-28 补充：在不开发登录页面的前提下，P0 自报档案、类别型个人基线和 Agent 反馈观察环已经落地。反馈仅影响后续表达偏好，不能改变确定性安全判断；基线只有在历史可靠样本达到门槛后才显示。

> 2026-08-28 宠物单元：广场已接入成员独立的便便宠物和每日打卡。宠物是长期陪伴与留存界面，不是新的医疗判断器；它只消费可靠摘要，样本不足时明确处于探索状态，娱乐数据与健康事实分表保存。

> 2026-08-29 社区单元：ANP 社区已形成“用户写下愿意公开的文字 → 逐帖确认 → Agent 别名发布 → 随时撤回”的最小闭环。家庭查看权不等于公开发布权，系统不会自动把健康事实变成社区内容。

> 2026-08-29 多 Agent 单元：综合分析已由单角色扮演升级为健康医生与生活教练分别执行、确定性仲裁收口的可审计四步 Run；红线安全规则始终优先。

> 2026-08-29 L1 匹配：ANP 已支持人工发起、对方接受和任一方断开的双向同意连接；连接本身不携带健康或家庭数据。

**已完成**：定位、五层架构、数据契约骨架、形状三档、真 agent 闭环认知、三层数据模型、问卷策略、技术选型（MVP 不绑框架，生产上 LangGraph）。

**已拍板**：记忆可见可改、成员待认领、低置信度明确无法判断、原始数据授权后上传、红线同步已授权家庭查看者。

**仍待硬件确认**：颜色/气味阈值、shape 三档能力、毫米波成员候选能力、通信与供电方案。

**最高优先级**：按上述固定顺序完成核心闭环；对外演示可用 mock 数据表现“主动”体验，但不得把尚未验证的硬件识别能力或安全流程描述为已实现。

# 已实现增量：健康周报闭环（2026-08-29）

核心健康链路新增周报事实层：用户在健康页主动生成周报，后端从已授权成员的可靠趋势聚合事实，规则引擎决定是否允许形成结论，LLM 仅解释已放行事实。生成结果持久化、可追溯、会产生站内通知，并通过成员查看/编辑权限隔离。

## 已实现增量：原始数据专项授权（2026-08-29）

原始传感数据继续默认留在设备本地。家庭所有者可针对指定设备、研究用途、数据类型和最长 30 天期限单独授权；设备端每次上传登记都实时复核授权。撤回或到期立即停止新上传，已有云端对象进入删除状态机，用户可以看到待删除/已完成状态。
