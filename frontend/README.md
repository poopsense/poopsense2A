# PoopSense Web / PWA

核心软件闭环的用户界面，当前包含：

- 家庭待认领箱：必须选择成员后才能确认，候选不会自动变成归属。
- 趋势页：用三条漫画式长期变化轨道整合形状、颜色和气味；底层仍使用类别占比与个人基线，不对类别求平均。
- 记录历史：可纠正归属，后端保留完整版本。
- 我的/设备：开发期配置 API、家庭 ID 和标签页级访问密钥。
- PWA 壳：manifest、图标和 service worker；静态界面可缓存，健康 API 不缓存。

## 用户任务优先的界面原则

- 首页只解决两件事：看懂今天的可靠结论、进入 Agent 医生；待认领只以轻提示出现。
- Agent 协作轨迹、模型与策略依据保留可审计，但默认折叠，不用工程术语抢占健康回答。
- 健康页默认展示频率、连续异常与类别基线；周报、健康档案、Agent 记忆和历史记录按需展开。
- 广场先展示社区、健康交流和宠物三个入口，动态列表与 Agent 连接作为次级内容展开。
- “我的”承载成员、授权、隐私和用户能理解的健康伙伴设置；设备卡缩小并后置。Skill、模型版本和通知审计等系统架构信息不在普通用户前台展示。

## 传感器结果到卡通形象

首页不从 Agent 文案猜测形象，而是读取后端返回的 `visual_profile`：

- `normal / elongated` → 顺滑长条；
- `hard / scattered` → 分散颗粒；
- `loose / irregular` → 不规则形态；
- `compact` → 紧实成团；
- 评估不可靠、置信度不足或形态未定义 → 不确定形象，不展示具体传感标签。

`visual_profile` 同时保留形状、颜色和气味的值、置信度、来源、模型版本及映射版本，便于审计。当前黄色角色图位于 `public/poop-shape-*-yellow-v2.png`，原 `v1` 素材保留用于回退。

## 启动

比赛演示优先在项目根目录使用一键启动（会复用已经健康的服务，并拒绝复用旧版或异常端口）：

```powershell
.\start_demo.ps1 -TestModel
```

日常开发也可以先启动后端，再运行：

```powershell
cd frontend
npm install
npm run dev -- --host 127.0.0.1
```

打开 `http://127.0.0.1:5173`。

## 验证

```powershell
npm run build
npm test
```

项目根目录的只读演示预检不会修改业务数据：

```powershell
.\check_demo.ps1
# 额外发送一条真实模型消息，用于上场前最终检查
.\check_demo.ps1 -TestModel
```

开发密钥仅存在当前浏览器标签页的 `sessionStorage`。正式环境必须关闭后端 demo bootstrap，并接入真实登录；前端不能把生产长期凭证写入打包文件或长期浏览器存储。
